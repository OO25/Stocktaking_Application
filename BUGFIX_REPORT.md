**Stocktaking review fixes**

Work is on `codex/bugfix-stocktaking-review`, created after fetching origin and switching to `dev`. The branch starts at development commit `0a786c644bf637ed5551e4bdff2033b0ee88bad6`. Changes are local and uncommitted; nothing has been pushed or deployed.

| Reported issue | Change |
| --- | --- |
| Misleading arrow and placement of Save/Submit | Removed the decorative external-link arrow and generic Action card. Save and Submit now sit in a clearly labelled footer beneath the stocktake tables, using the existing buttons, colours, borders, and spacing. |
| Editing a draft assignment selects In Progress | The status editor starts with the assignment's actual status and includes Draft as an explicit option. Opening it makes no write request. Saving without changing the selection preserves Draft. |
| Dragging out of an input dismisses its modal | Added a shared ModalBackdrop component. Dismissal requires the gesture to start and finish on the backdrop. Applied it to the custom category, supplier, unit, product, user, assignment, and temporary-item modals. Existing discard confirmations still work for deliberate backdrop clicks. |
| Browser tabs have indistinguishable titles | Titles now include the current page and application name. Stocktake detail titles include the assignment name; the login page also has its own title. |
| Category Excel and CSV options do nothing | Both downloads work. Excel produces a real XLSX workbook with a bold header, readable column widths, and a frozen header row. Exports include all matching categories, across pagination, in the selected sort order. CSV escapes quotes and delimiters and protects against formula interpretation. |
| Duplicate category names and duplicate dropdown selection | Added trimmed, case-insensitive name validation on category create/update in both the form and API, scoped to category type. Product form command options now use stable IDs, with names retained as search keywords. Existing duplicate display names remain individually selectable. |
| Inconsistent ordering and hidden Created-date sorting | Products default to alphabetical order and no longer offer the invisible Created-date sort in the UI. Categories, suppliers, units, outlets, and users have consistent A–Z/Z–A controls. Reference names compare case-insensitively; sorting happens before pagination. Product price sorting and existing search/type filters remain available. |
| Delete icons disappear or allow deletion of in-use products | Added a shared delete control that remains visible, becomes grey and disabled when in use, and explains why on hover/focus. Product responses now include stocktake usage. Category/unit/outlet usage includes additional references such as temporary items, child groups, sessions, and user assignments where applicable. |
| Raw duplicate-key errors for units | Add/edit forms validate unit names before submitting. The API also rejects trimmed, case-insensitive duplicates with a friendly conflict message, and rejects whitespace-only names. Database uniqueness failures are translated into the same friendly message. |
| Management pages and writes accessible to non-admins | All seven management pages are nested under an admin route guard. Category, outlet, and product create/update/delete endpoints now require the admin role, matching the existing supplier, unit, and user restrictions. Empty sidebar groups are hidden and management breadcrumb navigation is role-aware. |
| Access to other outlets' records | Outlet and product reads for non-admins are scoped to database-backed outlet assignments. Authenticated reference lookups needed for counting remain available. Viewers cannot write stocktake entries, temporary items, or submissions, and see read-only stocktake controls. |
| Admins cannot reopen submitted counts | Added an admin-only Reopen action and confirmation on the stocktake detail page. It returns the count to In Progress through the existing admin-only status API and retains entries. This includes current-month counts. |
| Dashboard always shows the same inventory alerts | Removed hard-coded products, quantities, and urgency badges. The existing card now explains that alerts are unavailable because reorder levels have not been configured. No unsupported stock-level calculations or fictional thresholds were introduced. |
| Future stocktakes labelled Previous | Renamed the non-current-month section to Other Months’ Stocktakes, accurately covering both past and future periods. |
| Submission causes an unsaved-changes warning | Successful finalization now updates the saved state and navigates directly to the list. Removed timeout-based navigation through a stale unsaved-change closure. Failed saves continue to display an error and retain the editor. |
| Filtering products by outlet hides their other outlets | The outlet condition now uses an existence check, leaving the result's outlet aggregation intact. Admins see the full assignment list for matching products. Non-admin results remain limited to their authorized outlets. |

An additional data-integrity fix makes product deletion transactional: if stocktake references prevent deletion, removal of outlet assignments is rolled back. Previously a failed product delete could remove those links first.

Implementation follows the existing React, Tailwind, and shared UI conventions. Small shared components handle backdrop dismissal, disabled delete actions, and name sorting. Excel generation is loaded only when requested. New dependencies are `write-excel-file` for XLSX output and development-only `read-excel-file`, Playwright, and PGlite for verification. Test mode skips the application's database prewarm so regression tests never need a live database.

Verification:

- `npm test`: 12 passing tests. These exercise real Express routes with signed test tokens and an isolated PostgreSQL-compatible PGlite database, plus CSV escaping and XLSX round-trip reading. Coverage includes 54 unauthorized management-write combinations, outlet filtering/scoping, rollback on failed deletion, category/unit duplicates, database uniqueness, reference usage, reopening, viewer restrictions, and sorting before pagination.
- `npm run test:browser`: 9 passing Chrome tests with isolated API fixtures. Coverage includes direct management URLs, navigation visibility, drag-outside behavior, duplicate form validation, both downloads, duplicate-name dropdown selection, draft preservation, sorting, tab titles, submission navigation, viewer controls, and reopening.
- `npm run build`: production build succeeds. The existing main application bundle still produces Vite's large-chunk warning; the new export module is loaded separately.
- `git diff --check`: clean. The stocktake footer was also inspected in a rendered desktop screenshot.

Deployment requires migration `009_unique-reference-names.sql`, which adds normalized unique indexes for food groups, packaging types, and units. It has been tested against the isolated database but has **not** been run against a live database. If existing duplicate names are present, the migration deliberately fails and rolls back rather than choosing which records to merge or delete. Rename conflicting records before running `npm run migrate --workspace=server`. Until this migration is applied, application validation does not provide the database's protection against concurrent duplicate requests.

The browser tests use fixtures and do not replace an authenticated smoke test against the deployment's real database. Inventory alert calculations remain unavailable until the product has a source of reorder thresholds.

`npm audit` reports 20 dependency findings: 3 low, 4 moderate, 11 high, and 2 critical. Every reported package/version was compared with the original development lockfile and was already present there. These existing dependency upgrades were not mixed into this bugfix branch.
